# Лабораторна робота №22

## Тема
**LSP: виявлення порушень і альтернативи (Банківські рахунки)**


## Мета роботи
Поглибити розуміння **Принципу підстановки Лісков (LSP)** та навчитися:
 Ідентифікувати порушення LSP в ієрархіях класів  
 Застосовувати альтернативні підходи (**композиція**, зміна ієрархії)  
  для створення **LSP-сумісних рішень**


## Теоретичні відомості

**Принцип підстановки Лісков (LSP):**  
Похідні класи повинні замінювати базові без зміни очікуваної поведінки клієнтського коду.

**Порушення LSP:**  
Виникає, коли похідний клас посилює передумови або змінює очікувану поведінку базового класу.

**Композиція vs Наслідування:**  
Використання композиції дозволяє уникнути порушень контрактів базових класів.

**Банківські рахунки:**  
 `Account` — дозволяє знімати кошти  
 `SavingsAccount` — вводить обмеження мінімального балансу → порушує LSP


## Хід роботи

1. Створено консольний проєкт `lab22`.
2. Реалізовано початкову ієрархію класів:
    `Account` – базовий клас з методом `Withdraw`  
    `SavingsAccount` – похідний клас, який забороняє знімати кошти нижче `minimumBalance`
3. Створено клієнтський метод `ProcessAccount`, який демонструє порушення LSP:
    Виклик `Withdraw` для `SavingsAccount` кидає виняток, хоча клієнт очікує успішну операцію
4. Проведено аналіз порушення LSP:
    `SavingsAccount` посилює передумови → порушує контракт базового класу
5. Реалізовано альтернативне рішення через композицію:
    Клас `LSPCompliantAccount` підтримує опціональний `minimumBalance`  
    Клієнтський код працює з будь-яким рахунком без порушення очікувань
6. Продемонстровано коректну роботу альтернативного рішення в `Main`:
    Створено об’єкти `standardAcc` та `savingsAcc`  
    Виклик `Withdraw` працює без винятків та дотримується правил контракту


## Результати роботи

 Початкова ієрархія `Account / SavingsAccount` **порушує LSP**  
 Альтернативна реалізація через композицію (`LSPCompliantAccount`) **дотримується LSP**  
 Клієнтський код **коректно працює з усіма об’єктами рахунків**  
 Консольна демонстрація показує правильне зняття коштів та обмеження мінімального балансу


## Висновки

 Розглянуто **принцип Liskov Substitution Principle** та його значення для безпечного наслідування  
 Продемонстровано, як **посилення передумов у похідному класі порушує LSP**  
 Використання **композиції дозволяє дотримуватися LSP** та уникати порушень контракту  
 Мета лабораторної роботи досягнута: отримано **глибоке розуміння LSP** та практичні навички застосування альтернативних підходів
