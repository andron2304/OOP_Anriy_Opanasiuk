# Юніт-тестування: теорія та практика

## Вступ

Юніт тестування це метод автоматизованого тестування, при якому перевіряється найменша одиниця коду метод або клас ізольовано від інших компонентів системи.

Основна мета юніт-тестів перевірити правильність роботи бізнес логіки та забезпечити можливість безпечного рефакторингу коду.

### Переваги

- Раннє виявлення помилок під час розробки  
- Швидке виконання тестів  
- Безпечний рефакторинг  
- Документування поведінки коду  
- Покращення архітектури та слабке зв’язування компонентів  

### Обмеження

- Не перевіряє взаємодію між різними частинами системи  
- Не виявляє проблем інтеграції з базами даних або зовнішніми сервісами  
- Потребує додаткового часу на написання та підтримку тестів  

## Порівняння з інтеграційним тестуванням

Юніт тестування перевіряє окремий метод або клас ізольовано від інших компонентів системи. Інтеграційне тестування, навпаки, перевіряє взаємодію між різними компонентами та модулями.

Юніт тестування зазвичай використовує mock-об’єкти для заміни зовнішніх залежностей, тоді як інтеграційне тестування працює з реальними базами даних, сервісами або API.

Юніт тести виконуються дуже швидко, оскільки не залежать від зовнішніх ресурсів. Інтеграційні тести виконуються повільніше через необхідність взаємодії з реальними компонентами системи.

Юніт тестування є ізольованим і спрямоване на перевірку логіки конкретного класу або методу. Інтеграційне тестування є комплексним і перевіряє коректність роботи системи в цілому.

Юніт-тести перевіряють логіку окремих частин програми, тоді як інтеграційні тести перевіряють правильність роботи системи в цілому.

using System;

public class Calculator
{
    public int Add(int a, int b)
    {
        return a + b;
    }

    public int Divide(int a, int b)
    {
        if (b == 0)
            throw new ArgumentException("Division by zero");

        return a / b;
    }

    public bool IsPositive(int number)
    {
        return number > 0;
    }
}
