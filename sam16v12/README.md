# Самостійна робота №16
## Тема: Схема розподілу відповідальностей модуля

### Мета роботи
Навчитися застосовувати принцип єдиної відповідальності (SRP) шляхом
декомпозиції складного класу на менші, спеціалізовані компоненти, а також
використати принцип інверсії залежностей (DIP).


## Опис варіанту
**Варіант 12 – NotificationSender**

Початковий клас виконує:
- формування повідомлення
- вибір каналу
- відправку повідомлення
- логування

Це порушує принцип SRP.


## Рефакторинг
Функціональність розділено на окремі інтерфейси:
- IMessageFormatter
- IChannelSelector
- IEmailSender
- ISmsSender

Клас `NotificationService` відповідає лише за координацію процесу.


## UML-діаграма
Для візуалізації структури використано діаграму класів UML (Mermaid).


## Висновок
Рефакторинг дозволив:
- усунути God Object
- підвищити читабельність та підтримуваність коду
- забезпечити слабку зв’язаність компонентів
- дотриматися принципів SRP та DIP
