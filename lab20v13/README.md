# IndependentWork20

Консольний проєкт для лабораторної роботи №20, Варіант 13. Реалізовано систему обробки даних про книги з використанням патернів Strategy та Observer.

## Що реалізовано

- Інтерфейс `IDataProcessorStrategy` з методом `void Process(string data)`
- Стратегії:
  - `AddBookStrategy` — імітує додавання книги
  - `RemoveBookStrategy` — імітує видалення книги
  - `UpdateBookInfoStrategy` — імітує оновлення інформації про книгу
- Клас `DataContext` з можливістю зміни стратегії під час виконання
- Клас `DataPublisher` з подією `DataProcessed`
- Спостерігачі:
  - `LibraryCatalogObserver`
  - `NewArrivalsNotifierObserver`
- В `Main` показано зміну стратегій і сповіщення спостерігачів

## Як запустити

```bash
cd IndependentWork20
dotnet run
```

## Контрольні питання

1. Поясніть патерн Strategy. Як він дозволяє змінювати поведінку об’єкта під час виконання?
   - Strategy інкапсулює сімейство алгоритмів у окремі класи, кожен з яких реалізує один інтерфейс. Об’єкт, який використовує стратегію, може заміняти поточну реалізацію на іншу під час виконання через метод `SetStrategy`, тому поведінка змінюється динамічно без зміни самого об’єкта.

2. Поясніть патерн Observer. Як він забезпечує слабке зв’язування між суб’єктом та спостерігачами?
   - Observer визначає залежність «один-до-багатьох», коли один об’єкт повідомляє всіх підписаних спостерігачів про зміни стану. Суб’єкт не знає деталей кожного спостерігача, він просто викликає подію, а підписники самі обробляють сповіщення, що зменшує зв’язність.

3. Як події та делегати в C# використовуються для реалізації патерну Observer?
   - У C# делегати визначають тип підписника, а події забезпечують механізм реєстрації та виклику підписників. Суб’єкт оголошує подію, спостерігачі підписуються на неї своїми методами, і коли подія викликається, всі підписані методи виконуються.

4. Наведіть приклад, як комбінація Strategy та Observer може створити гнучку та розширювану систему.
   - У нашій системі `DataContext` використовує стратегію для обробки даних, яку можна змінювати під час виконання (шифрування, стиснення, логування). `DataPublisher` повідомляє спостерігачів про оброблені дані через подію, і кожен спостерігач робить свою дію. Це дозволяє додавати нові стратегії і спостерігачі без змін у центральній логіці.
