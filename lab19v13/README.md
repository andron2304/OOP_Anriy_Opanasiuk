# IndependentWork19

Консольний проєкт для лабораторної роботи №19. Реалізовано систему логування з використанням патернів "Factory Method" та "Singleton".

## Що реалізовано

- Інтерфейс `ILogger` з методом `void Log(string message)`
- Три реалізації `ILogger`:
  - `ConsoleLogger` — виводить повідомлення в консоль
  - `FileLogger` — імітує запис у файл, додаючи префікс `[FILE]`
  - `DatabaseLogger` — імітує запис у базу даних, додаючи префікс `[DB]`
- Абстрактна фабрика `LoggerFactory` з методом `protected abstract ILogger CreateLogger()` та `public void LogMessage(string message)`
- Конкретні фабрики:
  - `ConsoleLoggerFactory`
  - `FileLoggerFactory`
  - `DatabaseLoggerFactory`
- Синглтон `LoggerManager`, який керує поточною фабрикою логерів та делегує логування

## Як запустити

```bash
cd IndependentWork19
dotnet run
```

## Що демонструється в `Main`

- Отримання екземпляру `LoggerManager`
- Встановлення `ConsoleLoggerFactory` та кілька логів
- Перехід на `FileLoggerFactory` та кілька логів
- Перехід на `DatabaseLoggerFactory` та кілька логів

## Контрольні питання

1. Поясніть патерн Factory Method. Які проблеми він вирішує?
   - Factory Method визначає інтерфейс для створення об'єкта, але дозволяє підкласам вирішувати, який саме клас створювати. Це розділяє клієнтський код та конкретні реалізації, зменшує зв'язність і спрощує розширення системи без змін у клієнті.

2. Поясніть патерн Singleton. Коли його доцільно використовувати, а коли варто уникати?
   - Singleton гарантує, що клас має лише один екземпляр і надає глобальну точку доступу до цього екземпляра. Його доцільно використовувати для логгерів, конфігурацій, менеджерів ресурсів або інших сервісів, де потрібен єдиний стан. Варто уникати Singleton, коли потрібні тести із незалежними екземплярами або коли глобальний стан може ускладнити підтримку та масштабування.

3. Як ці два патерни можуть працювати разом для створення гнучкої та контрольованої системи?
   - Factory Method створює потрібний тип об'єкта через абстрактну фабрику, а Singleton забезпечує єдиного менеджера, який керує цією фабрикою. Разом вони дозволяють динамічно змінювати реалізацію під час виконання без зміни клієнтського коду, зберігаючи при цьому централізований контроль.

4. Які переваги дає використання абстракцій (інтерфейсів) у поєднанні з Factory Method та Singleton?
   - Абстракції дозволяють клієнту працювати з інтерфейсами замість конкретних класів, що спрощує заміну реалізацій і підтримку коду. У комбінації з Factory Method і Singleton це забезпечує слабке зв'язування, високу гнучкість, можливість додавати нові варіанти логерів і легке тестування, оскільки можна підставляти різні реалізації без зміни логіки.
