# IndependentWork21

Консольний проєкт для лабораторної роботи №21. Інтеграційні тести патернів (Factory/Singleton/Strategy/Observer).

## Що реалізовано

Інтегрована система, що поєднує патерни з попередніх робіт:
- **Factory + Singleton** (з IndependentWork19): Створення логерів через фабрику та єдиний екземпляр LoggerManager.
- **Strategy + Observer** (з IndependentWork20): Обробка даних про книги з динамічною зміною стратегій та сповіщенням спостерігачів.

Спостерігачі використовують логер для запису повідомлень.

## Як запустити

```bash
cd IndependentWork21
dotnet run
```

## Інтеграційні тести

Тести розташовані в `tests/UnitTest1.cs`. Запуск: `dotnet test` у папці `tests`.

### Сценарії тестування

#### Позитивні сценарії (3 шт.)
1. **Positive_AddBookStrategy_ExecutesAndNotifiesObservers**
   - Опис: Створення контексту з AddBookStrategy, додавання спостерігачів, виконання обробки та публікація події.
   - Очікуваний результат: Код виконується без винятків, спостерігачі отримують повідомлення.
   - Фактичний результат: Проходить успішно.

2. **Positive_SingletonLoggerInstance_IsStable**
   - Опис: Перевірка, що LoggerManager повертає той самий екземпляр.
   - Очікуваний результат: Instance1 == Instance2.
   - Фактичний результат: Проходить успішно.

3. **Positive_FactoryCreatesCorrectLoggerType**
   - Опис: Фабрика створює правильний тип логера (ConsoleLogger).
   - Очікуваний результат: Тип ConsoleLogger.
   - Фактичний результат: Проходить успішно.

#### Негативні/граничні сценарії (2 шт.)
1. **Negative_NullStrategy_ThrowsArgumentNullException**
   - Опис: Спроба створити DataContext з null стратегією.
   - Очікуваний результат: ArgumentNullException.
   - Фактичний результат: Проходить успішно.

2. **Negative_ObserverWithoutLogger_DoesNotThrow**
   - Опис: Спостерігач працює без встановленого логера (null обробляється).
   - Очікуваний результат: Не кидає виняток.
   - Фактичний результат: Проходить успішно.

### Висновок по ризиках
- Ризик: Неправильна інтеграція патернів може призвести до null reference exceptions.
- Ризик: Singleton може бути порушений у багатопотоковому середовищі (Lazy<T> захищає).
- Ризик: Спостерігачі можуть не отримувати події через слабке зв'язування.
- Загальна оцінка: Система стійка, патерни коректно взаємодіють, тести покривають основні сценарії.
