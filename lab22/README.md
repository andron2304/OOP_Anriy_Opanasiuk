# IndependentWork22

Консольний проєкт для лабораторної роботи №22, Варіант 13. Реалізовано систему одиниць виміру з використанням патернів Composite та Decorator.

## Що реалізовано

- Інтерфейс `IComponent` з методом `double GetValue()`
- Leaf класи: `LengthUnit` (Value, Unit), `WeightUnit` (Value, Unit)
- Composite клас: `MeasurementGroup` (List<IComponent>)
- Декоратори: `PrecisionDecorator` (округлює значення), `UnitConverterDecorator` (імітує конвертацію одиниць)
- В `Main` показано створення ієрархії та застосування декораторів

## Як запустити

```bash
cd IndependentWork22
dotnet run
```

## Контрольні питання

1. Поясніть патерн Composite. Як він дозволяє працювати з ієрархічними структурами?
   - Composite дозволяє трактувати окремі об'єкти та їхні композиції однаково через спільний інтерфейс. Це спрощує роботу з ієрархіями, оскільки клієнтський код не відрізняє листки від композитів, що забезпечує гнучкість та уніфікацію.

2. Поясніть патерн Decorator. У чому його перевага над наслідуванням для розширення функціональності?
   - Decorator динамічно додає функціональність до об'єктів, обгортаючи їх, без зміни класу. Перевага над наслідуванням: дозволяє комбінувати декоратори, уникати експоненційного зростання класів та додавати поведінку під час виконання.

3. Як можна комбінувати Composite та Decorator для створення складних та гнучких систем?
   - Composite створює ієрархію, а Decorator додає функціональність до будь-якого вузла ієрархії (листка чи композит). Це дозволяє декорувати як окремі елементи, так і цілі піддерева, забезпечуючи глибоку кастомізацію.

4. Наведіть приклад, коли використання Composite або Decorator є більш доцільним, ніж інші підходи.
   - Composite доцільний для файлових систем (папки містять файли та інші папки). Decorator — для UI елементів, де потрібно динамічно додавати стилі (рамки, тіні) без зміни базових класів.
