# Lab25 – Інтеграція патернів проєктування

## Тема

Інтеграція патернів (підготовка до екзамену).

## Мета роботи

Розробити консольну систему, що демонструє взаємодію компонентів, які реалізують патерни **Factory Method**, **Singleton**, **Strategy** та **Observer**, а також перевірити коректність їх спільної роботи.

## Опис проєкту

Проєкт являє собою консольний застосунок на C#, у якому реалізовано систему обробки даних з можливістю:

* динамічної зміни логера;
* динамічної зміни стратегії обробки даних;
* сповіщення спостерігачів про завершення обробки даних.

Усі патерни інтегровані між собою в одному застосунку.

## Використані патерни

### 1. Factory Method

Використовується для створення різних типів логерів без зміни коду клієнта.

* `LoggerFactory`
* `ConsoleLoggerFactory`
* `FileLoggerFactory`

### 2. Singleton

Забезпечує існування лише одного екземпляра менеджера логерів у програмі.

* `LoggerManager`

### 3. Strategy

Дозволяє змінювати алгоритм обробки даних під час виконання програми.

* `EncryptDataStrategy`
* `CompressDataStrategy`
* `DataContext`

### 4. Observer

Реалізує механізм підписки на подію завершення обробки даних.

* `DataPublisher`
* `ProcessingLoggerObserver`

## Сценарії демонстрації

### Сценарій 1 – Повна інтеграція

* Ініціалізація `ConsoleLogger`.
* Обробка даних стратегією шифрування.
* Сповіщення спостерігача.
* Виведення повідомлень у консоль.

### Сценарій 2 – Динамічна зміна логера

* Після першої обробки логер змінюється на файловий.
* Дані починають записуватись у файл `log.txt`.

### Сценарій 3 – Динамічна зміна стратегії

* Стратегія змінюється з шифрування на стиснення.
* Обробка даних відбувається за новим алгоритмом.

## Запуск проєкту

1. Відкрити проєкт у Visual Studio або VS Code.
2. Обрати конфігурацію **Console App (.NET)**.
3. Запустити файл `Program.cs`.
4. Перевірити вивід у консолі та файл `log.txt`.

## Очікуваний результат

* Повідомлення в консолі про обробку даних.
* Створення та оновлення файлу `log.txt`.
* Коректна робота всіх трьох сценаріїв.

## Висновок

У процесі виконання лабораторної роботи було інтегровано чотири патерни проєктування в одному застосунку. Це дозволило створити гнучку, розширювану та модульну архітектуру системи. Було продемонстровано можливість зміни поведінки програми під час виконання без зміни її основної структури, що відповідає принципам SOLID та сучасним підходам до розробки програмного забезпечення.
