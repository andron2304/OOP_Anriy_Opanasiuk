# IndependentWork23

Консольний проєкт для лабораторної роботи №23, Варіант 13.

## Що реалізовано

- **Adapter**: `IPrintJob` (Target), `LegacyPrinterDriver` (Adaptee), `PrinterDriverAdapter`.
- **Facade**: `DocumentFormatter`, `PrintQueue`, `PrinterFacade`.
- **Proxy**: `IPrinter`, `RealPrinter`, `SecurityPrinterProxy`, `CachingDataLoaderProxy`.

## Опис сценарію

Реалізовано систему друку документів, де старий драйвер принтера адаптується до сучасного інтерфейсу, фасад спрощує процес форматування, додавання до черги та друку, а проксі контролює доступ за роллю та кешує документи.

## Як запустити

```bash
cd IndependentWork23
dotnet run
```

## Контрольні питання

1. Як працює патерн Adapter і для чого він потрібен?
   - Adapter переводить інтерфейс одного класу у формат, який очікує клієнт. У нашому випадку `PrinterDriverAdapter` реалізує сучасний інтерфейс `IPrintJob` та адаптує виклики до старого `LegacyPrinterDriver`, який працює з байтовими даними.

2. Як Facade спрощує використання складної підсистеми?
   - Facade надає єдиний простий інтерфейс для набору класів підсистеми. `PrinterFacade` об'єднує форматування документа, додавання його до черги і друк, тому клієнт бачить лише один метод `PrintDocument`.

3. У чому різниця між Proxy та Adapter?
   - Adapter змінює інтерфейс об'єкта, щоб зробити його сумісним з клієнтом. Proxy ж зберігає той самий інтерфейс, але контролює доступ до реального об'єкта, додаючи функції, наприклад безпеку або кешування.

4. Наведіть приклад, коли Proxy з кешуванням корисний.
   - Proxy з кешуванням корисний, коли операція дорога або повільна, але результат можна повторно використовувати. У нашій лабораторній `CachingDataLoaderProxy` зберігає останній документ і не виконує повторний друк, якщо документ не змінився.
