## 1. Мета
Створити клас із мінімум 5 властивостями, виконати його серіалізацію у формати JSON та XML і порівняти отримані результати.

## 2. Вихідний код класу

```csharp
public class Student
{
    public int Id { get; set; }
    public string Name { get; set; }
    public int Age { get; set; }
    public string Major { get; set; }
    public double AverageGrade { get; set; }
}
```

## 3. Результати серіалізації

### Формат JSON:
```json
{
  "Id": 101,
  "Name": "Андрій",
  "Age": 18,
  "Major": "Інженерія програмного забезпечення",
  "AverageGrade": 95.5
}
```

### Формат XML:
```xml
<?xml version="1.0" encoding="utf-16"?>
<Student xmlns:xsi="[http://www.w3.org/2001/XMLSchema-instance](http://www.w3.org/2001/XMLSchema-instance)" xmlns:xsd="[http://www.w3.org/2001/XMLSchema](http://www.w3.org/2001/XMLSchema)">
  <Id>101</Id>
  <Name>Андрій</Name>
  <Age>18</Age>
  <Major>Інженерія програмного забезпечення</Major>
  <AverageGrade>95.5</AverageGrade>
</Student>
```

## 4. Порівняння результатів

З отриманих результатів чітко видно структурні відмінності між форматами:
* **JSON** є набагато компактнішим. Він використовує фігурні дужки та прості пари "ключ-значення", що робить його розмір меншим і легшим для читання людиною. 
* **XML** є більш "багатослівним" (verbose), оскільки для кожної властивості використовується відкриваючий та закриваючий тег (наприклад, `<Name>Андрій</Name>`). Це збільшує загальний обсяг збережених даних, але робить структуру дуже чіткою та самоописовою.

## 5. Реальні сценарії використання

**Сценарії для JSON:**
1. Обмін даними у сучасних веб-додатках (спілкування між Frontend-частиною сайту та Backend-сервером через REST API).
2. Зберігання налаштувань програм (наприклад, файли конфігурації `appsettings.json` у .NET).

**Сценарії для XML:**
1. Інтеграція з корпоративними (Enterprise) системами та застарілими сервісами (SOAP API).
2. Обмін складними документами, де потрібна сувора валідація структури за допомогою XSD-схем (наприклад, податкові звіти, банківські транзакції).

## 6. Висновок

**Чому JSON домінує у вебі, а XML залишається в Enterprise?**
JSON став стандартом де-факто для веб-додатків через свою легкість та природну сумісність із JavaScript (браузерам дуже легко його обробляти). Його менший розмір дозволяє економити трафік мобільних пристроїв та прискорює завантаження сторінок. 

Проте XML не втрачає своїх позицій у великому корпоративному середовищі. Це пов'язано з тим, що XML має потужні вбудовані інструменти для валідації (XSD) та підтримку просторів імен. У банківській сфері чи державних реєстрах надійність, сувора типізація та перевірка структури документа перед його обробкою є критично важливими, і з цими задачами XML справляється краще за JSON.
